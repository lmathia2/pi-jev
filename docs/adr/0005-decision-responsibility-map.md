# ADR 5: Decision inputs, proposals and Pi authority

Status: accepted. Date: 2026-09-21.

## Problem

A semantic proposal is not an executable action. For example, selecting a cheaper model does not establish that its context window fits, and selecting `proceed` does not grant tool permissions. Each integration needs an explicit boundary between judgment and application.

## Shared decision boundary

Pi constructs a versioned request containing bounded private features, boundary/state identity and authorized candidates. The reusable decision registry snapshots inputs, validates finite answers, enforces cancellation/timeouts/invocation limits and records identity/usage. Implementations return proposals, abstentions or failures, not tool/session handles. Trusted executable plugins are not sandboxed by this interface.

Jev is one configurable implementation, not the authority layer. Its adapter uses Choice for one candidate, independent binary Noul judgments for subsets, and raw binary probabilities for context retention. Subset uncertainty retains candidates; selection below the configured probability abstains. Raw context scores are thresholded by Pi, not the adapter. Baseline, heuristic, recorded or other registered implementations can replace Jev without changing the host boundary.

Instructions, criteria, descriptions and tunable thresholds are policy/configuration data. Pi retains schemas, candidate authority, permission checks, structural invariants, budgets, persistence and fallback. Learning imports candidates offline; it does not modify these invariants or automatically promote live behavior. See [ADR 1](0001-reusable-decisions-and-policy-plugins.md) and [ADR 3](0003-evidence-and-offline-learning.md).

## Normal-session responsibility map

| Definition / boundary | Inputs supplied by Pi | Decision proposal | Pi application and limits |
|---|---|---|---|
| `generation.phase/v1`, newly settled noninitial tool boundary | Task, current phase, configured transition descriptions, bounded tool results/history, pending input and context usage | Current phase or one permitted next phase | Check freshness and transition graph; persist once-per-result check and accepted transition under a separate budget. Stay does not reroute. A turn or retry alone is not a phase transition. |
| `generation.route/v1`, `before_generation` | Task/phase, current model-effort-tools, eligible complete presets, bounded outcomes/prior decisions, context/cache facts and optional host features | Preset ID or `keep_current` | Filter availability, scope, capability, supported effort, required tools and context feasibility; calculate stay/switch costs, recheck auth/freshness, commit the complete preset before prompt construction. Unknown costs cannot prove switching savings; explicit bounded capability escalation is separate. |
| `skills.select/v1`, phase preparation before routing costs | Full loaded eligible roster/descriptions, explicit skill names, task/phase, pending input and context usage | Subset of loaded skill IDs | Restore explicit selections, preserve roster order, persist phase visibility and edit structured prompt options. Disabled automatic skills stay excluded unless explicit. No skill installation or arbitrary path generation. |
| `retrieval.rank/v1`, fresh built-in `grep`/`find` result | Bounded task/recent outcomes and search lines with file groups/required markers | Subset of candidate IDs | Preserve required/dependent groups and exact retained text; skip truncated/unsupported results, enforce minimum reduction and save original before replacement. `recall_output` restores exact text. This is relevance filtering, not source verification. |
| `output.select/v1`, eligible fresh `tool_result` | Bounded task/recent outcomes and deterministic line blocks/required markers | Subset of block IDs | Preserve required blocks, mark omissions, require meaningful reduction and saved original. Errors, reads/edits/writes, diffs, unsupported content and recognized full-output requests bypass trimming. It does not paraphrase or rewrite older history. |
| `tools.review/v1`, configured `tool_call` | Proposed tool name/arguments, task, bounded recent outcomes, pending input and optional host features | `proceed`, `request_review` or `block` | `request_review` and `block` block the call; `proceed` adds no objection, not permission. Stale/cancelled review blocks; transport/invalid results use configured `onFailure`. Existing deterministic execution/permission checks remain authoritative. |
| `completion.verify/v1`, `agent_end` | Task/recent outcomes, pending input, latest tool failures by tool-and-argument identity | `accept`, `verify` or `clarify` | Unresolved recorded failures force verification; pending user input/cancellation wins. Persist per-task pass count before queuing a configured fixed follow-up, bounded to 1–3 passes. Acceptance means no added follow-up, not proof of correctness. |
| `context.retention/v1`, preconstruction `context_management` | Raw history/current input projected into a bounded ordered overview, independent call/result excerpts, task/phase/model/effort/tools, pending input, compaction instructions and estimated capacity/target | Complete `[0,1]` score map for `${toolId}:call` and `${toolId}:result` | Keep protected/unjudged interactions; use configurable thresholds for keep/excerpt/paired omission. Pi owns prompt-overhead accounting, cache identity/usage/prices and optional cache preference. Check structure and estimated budget before construction, preserve originals/recall, or request existing summary fallback. No post-render gate or exact fit guarantee. See [ADR 4](0004-context-window-management.md). |

## Assumptions and limitations by area

- Phase and routing: descriptions and finite graphs are operator-supplied; semantic phase accuracy is unmeasured. Pricing, remaining-request horizons and prefix reuse are estimates, not future provider guarantees. Normal-session commit is synchronous in memory, not a transactional disk operation; later user/listener changes win. [ADR 2](0002-phase-boundaries-and-host-authority.md) describes ordering and persistence.
- Skills: explicit names are recognized from supported textual forms, not arbitrary natural-language references. Selection changes prompt visibility, not skill contents or trust. A phase-pinned subset may need a new boundary to change automatically.
- Retrieval: built-in grouping depends on recognized text formats; uncertain/unparsed groups are protected. Custom retrieval sources must supply their own groups, required evidence and token counts. Excerpts guide further reads and do not prove factual claims.
- Fresh output: protection uses deterministic tool/content patterns and task terms, not a complete interpretation of user intent. Semantic omission can still lose useful evidence; recall availability is recovery, not evidence that the model will request it.
- Review: the bounded snapshot may omit facts relevant to safety. It is advisory policy enforcement, not a sandbox, approval service or permission grant. The operator chooses failure behavior explicitly.
- Completion: `isError` and identical tool/argument retries approximate unresolved checks; a successful tool may still contain failed assertions or an incorrect answer. Pass exhaustion stops extra review, not establishes completion.
- Historical context: bounded excerpts can miss middle-of-result facts; user/assistant text, errors, multimodal and recent/protected interactions remain intact during selection. Existing fallback summaries remain lossy. Token accounting uses serialized-size/overhead heuristics; render mismatches use provider overflow recovery, and the legacy summarizer's own request is not bounded by this preparation. Cache-aware and cache-unaware traces are in ADR 4.

## Legacy and injected host boundaries

Legacy `jev.mode: "route"` is separate: `before_agent_start` sends task text to the old router, selects `fast`, `standard`, `deep` or `research`, applies probability/fit thresholds and maps the label to configured profile fields. It does not acquire the new private-state, phase-pinning or cache-admission guarantees. Default `off` makes no semantic routing calls; local recall can remain available for saved originals.

The durable adapter invokes `generation.route/v1` through the same registry, but its host supplies private snapshots, phase identity, complete lane configurations and final live admission. The driver checkpoints the selected configuration and reuses it on retry. This is an explicit lower-level integration, not the normal CLI's execution path.

`context.select/v1` and `tools.profile/v1` are reusable library contracts, not additional automatic normal-session controllers. Custom context helpers preserve caller-marked required/dependent candidates and return unchanged candidates on invalid/failing proposals. Custom retrieval token limits cannot discard required evidence to force a fit; its host must compact/defer. Automatic specialist dispatch, semantic recovery and source-evidence verification remain deferred rather than implicit consequences of these helpers.
